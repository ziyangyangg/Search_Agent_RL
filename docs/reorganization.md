# 工程重组与发布标准

## 组织原则

新项目围绕稳定接口组织：模型负责生成标准响应；工具负责单一能力；运行器负责循环和预算；
评估器负责可验证结果；训练后端负责参数更新。依赖方向保持单向，模型与工具不依赖训练框架。
运行时错误、失败轨迹与未完成任务要可见，不能被格式清理和兜底算法掩盖。

原始源码与资产保持原位，以路径引用，不打包模型和数据。商业指南、水印文件、空日志和
无法追溯的成绩图不进入新项目。已有开源代码的许可证和作者声明必须保留；不把去水印
或重排商业文档作为新文档生产方式。

## 本次实现与未实现

| 状态 | 内容 |
|---|---|
| 已实现 | 可安装 Python 包、结构化工具协议、唯一执行循环、模型 HTTP 接口、运行预算与轨迹 |
| 已实现 | 文本文件列表／读取／创建、schema 校验、默认拒绝写、禁止覆盖、路径约束 |
| 已实现 | 明确标识的 SQLite 检索、严格 QA 评估、逐题输出与数据哈希、CPU 回归测试 |
| 已实现 | 旧源码 diff 生成器、审阅哈希、漂移检查、备份与失败回滚 |
| 已准备 | 新代码安装到外接硬盘的脚本；当前会话对该卷无写权限，尚未执行 |
| 未实现 | 训练引擎整合、sampler token IDs/logprobs 捕获、GiGPO／ABC 算法接入 |
| 未实现 | 邮件、日历、浏览器、Office 二进制格式、MCP、组织身份与多租户服务 |
| 未完成 | GPU 训练、真实模型验收、真实办公 benchmark、安全红队测试 |

`completed` 仅表示运行器拿到完整文本答案，不表示答案正确或任务已验证成功。
办公任务应由 verifier 检查文件／数据库／应用状态；这不能靠模型自述替代。

## 分阶段验收

1. **来源与正确性**：修复旧奖励来源与验证 metadata，固定数据／检索／解码／分母，保存逐题证据。
2. **运行基线**：旧3B模型走旧标签协议，新强模型走原生工具协议，分别测试。记录失败原因和成本。
3. **训练改进**：先做原GRPO与修正GRPO对照，再单独比较GiGPO。每次只改变明确因素。
4. **办公试用**：先做资料整理和新报告产出。工作空间独立，默认只读，验证产物、引用与不可覆盖约束。
5. **开放发布**：在新Git仓库提交源码、测试、公开样例和可重放评估配置；不上传私有轨迹、权重或原始数据。

真正对外声明“可部署”前，须有真实端点集成测试、任务终态验证、失败恢复、操作幂等、权限隔离、
私密数据与API数据流说明。多用户服务还需要认证、配额和任务持久化；本次CLI基础版不包含这些。

## 研究定位

可形成两个清晰贡献：可靠的 Agent RL 实验底座，以及可验证的文档办公 Agent。
前者比较训练算法对工具决策的影响，后者比较实际任务完成、约束违规和执行成本。
共享运行与轨迹接口，分别建立评测，避免用问答 EM 代替办公能力，或将工程整理当作算法贡献。
