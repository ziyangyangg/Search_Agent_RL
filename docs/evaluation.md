# 评估协议

输入 JSONL 每行包含唯一 `id`、非空 `question`、非空答案列表 `golden_answers`。gold 只进入评分器，不进入模型消息。

| 模式 | 信息与预算 |
| --- | --- |
| direct | 问题，1 次模型回合 |
| rag | 问题和一次 top-3 检索，1 次模型回合 |
| agent | 问题与检索工具，最多 8 次模型回合、默认 12 次工具调用 |

三种模式预算不同，比较质量时同时报告 token、调用数与轨迹耗时。

预测在看到 gold 前固定。归一化采用小写、去英文标点/冠词、合并空白；strict EM 比较完整归一化答案，token F1 比较词项重叠。多个合法参考答案可取最好匹配，但不允许按 gold 挑选预测的不同改写。`London. Paris` 对 `London` 的 strict EM 为 0。EM 区间为 95% Wilson 区间。

非 `completed` 的预测记为空字符串，仍保留分母；数据/检索错误显式终止。每题写出并 flush，当前没有自动续评，也不保证突然掉电后的持久性。

| 输出 | 内容 |
| --- | --- |
| `manifest.json` | 数据/索引哈希、模式、条数和配置 |
| `predictions.jsonl` | 固定预测、gold、状态和用量 |
| `traces.jsonl` | 实际角色消息与事件耗时 |
| `summary.json` | 全部完成后的指标和状态汇总 |

目录必须是新目录。只有 predictions 文件不代表全量完成，要核对 summary 的 `complete` 和条数。

旧项目有 500 行评估、41,897 篇小语料和权重，但 15 份日志为空，历史 44.80% 缺少可复核原始结果。旧评分还在看 gold 后取原答案/截短答案更高分；新旧成绩需统一数据、检索、解码与协议后重跑，不能直接比较。

仓库合成样例的分数只是软件回归，真实模型能力另行验收。运行命令见 [README](../README.md) 和[使用指南](getting-started.md)。
